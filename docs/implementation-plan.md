## 第一阶段的第一步

先搭清楚两层服务：

```text
调用者 → 8000：自己实现的网关 → 30001：负责推理的引擎
```

- 网关处理“谁能调用、排多久、是否超额、怎么记账、如何返回结果”。
- 引擎处理“如何把输入变成模型输出”。CPU 自测阶段由独立 fixture 提供确定性输出，之后替换成 SGLang。
- `/healthz` 的 `ready` 代表网关依赖的引擎已可用。网关进程存在，但引擎未就绪时应返回 503。

第一个可观察的实验：引擎可用时 `/healthz` 返回 200；仅停止本次测试创建的引擎后返回 503；恢复后重新返回 200。接着验证无凭据访问模型接口被拒绝。这一步先建立正确的服务边界。
